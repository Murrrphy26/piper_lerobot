# pi05 远程异步推理使用说明

本文档说明如何在 **两台机器** 上运行 Piper 双臂真机 + 远程 pi05 推理（LeRobot Async Inference）。

## 架构概览

```
┌─────────────────────┐         SSH 隧道          ┌──────────────────────┐
│  工控机              │  127.0.0.1:8080 ────────► │  远程 GPU 服务器       │
│  (agilex)           │ssdsdfd│  (allinai2)          │
│                     │      gRPC (obs/action)    │                      │
│  - 4 路相机          │ ◄──────────────────────► │  - Policy Server     │
│  - Piper 机械臂      │                           │  - pi05 模型推理      │
│  - Robot Client     │                           │  - CUDA              │
│  - SSH 隧道         │                           │                      │
└─────────────────────┘                           └──────────────────────┘
```

| 机器 | 角色 | 仓库路径（示例） | 运行内容 |
|------|------|------------------|----------|
| 远程 GPU 服务器 (allinai2) | 推理端 | `/mnt/disk/fyx/piper` | Policy Server |
| 工控机 (agilex) | 真机端 | `~/code/yjw/piper` | SSH 隧道 + Robot Client |

**核心配置文件：** `configs/record_pick_cube_pi05.json`

## 前置条件

### 1. 代码与路径一致

两台机器上的 piper 仓库需保持**相同的相对路径结构**，尤其是：

- checkpoint：`outputs/train/pi05_cube_pi05_v1/checkpoints/last/pretrained_model`
- 数据集元信息：`data/lerobot/local/cube_pi05_v1/meta/info.json`

### 2. 网络与 SSH

- 工控机可 SSH 到 allinai2：`ssh allinai2`
- 工控机 `~/.ssh/config` 中配置好 `allinai2` 主机别名

### 3. 依赖安装(已完成)
```bash
conda activate piper
```
**远程 GPU 服务器 (allinai2)：**

```bash
cd /mnt/disk/fyx/piper
pip install "lerobot[async,pi]" grpcio
```

**工控机：**

```bash
cd ~/code/yjw/piper 
pip install "lerobot[async]" grpcio opencv-python
```

建议两端 `lerobot` 版本一致（例如均为 `0.5.1`），避免 pickle 反序列化不兼容。

### 4. 硬件

- 工控机：Piper 双臂 CAN（默认 `can2` / `can0`）、4 路 USB 相机
- 远程 GPU 服务器：NVIDIA GPU（pi05 推理，建议 bf16 + 5 diffusion steps）

## 快速启动（推荐流程）

必须按顺序执行，**不可跳步**。

### 步骤 1：在远程 GPU 服务器启动 Policy Server

```bash
ssh allinai2
cd /mnt/disk/fyx/piper
bash scripts/start_policy_server_pi05.sh
```

**等待出现以下日志后再进行下一步：**

```
INFO ... Preloading policy at startup | type=pi05 | path=outputs/train/...
INFO ... Startup preload finished in XXXs
INFO ... PolicyServer started on 0.0.0.0:8080
```

> 首次启动预加载约 **1–3 分钟**（`policy_server.preload_at_startup: true`）。  
> 预加载完成后 Server 才开始监听 8080。

### 步骤 2：在工控机开启 SSH 隧道（保持终端不关）

新开终端：

```bash
cd ~/piper
bash scripts/ssh_tunnel_policy_server.sh
```

正常输出示例：

```
Opening SSH tunnel for policy server gRPC.
  local:  127.0.0.1:8080
  remote: 127.0.0.1:8080
  ssh host: allinai2
```

**此终端必须保持运行**，关闭即断连。

### 步骤 3：在工控机启动 Robot Client

再开一个终端：

```bash
cd ~/piper
bash scripts/run_async_policy_client_pi05_remote.sh
```

等价于：

```bash
bash scripts/run_async_policy_client_pi05.sh configs/record_pick_cube_pi05.json
```

脚本会自动执行 CAN 初始化（`bringup_can.sh`）和手臂复位（`reset_arms.sh`）。若已手动完成，可跳过：

```bash
SKIP_BRINGUP=true SKIP_RESET=true bash scripts/run_async_policy_client_pi05_remote.sh
```

## Dry Run 与真机执行

### Dry Run（默认，推荐先做）

`configs/record_pick_cube_pi05.json`：

```json
"async_inference": {
  "execute": false
}
```

- 只打印 `pred` / `send` / `delta`，**机械臂不动**
- 用于确认远程推理链路、动作数值是否合理

### 真机执行

**只需修改工控机 JSON**，Server 端无需改动：

```json
"async_inference": {
  "execute": true
}
```

建议步骤：

1. 先 dry-run 确认 step 连续输出、Server 持续推理
2. 设 `execute: true`，先用较短 `duration`（如 `10.0`）试跑
3. 确认安全后恢复正常 `duration`

相关安全参数（`policy_live` / `async_inference` 均可覆盖）：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `max_joint_step_rad` | `0.025` | 单步最大关节变化（弧度） |
| `max_gripper_step_m` | `0.003` | 单步最大夹爪变化（米） |
| `smoothing_alpha` | `0.25` | 动作平滑系数（越小越保守） |
| `control_speed` | `10` | 机械臂运动速度 |

## 配置说明

所有参数集中在 `configs/record_pick_cube_pi05.json`。

### `policy_server`（远程 GPU 服务器读取）

| 字段 | 说明 |
|------|------|
| `host` / `port` | 监听地址，默认 `0.0.0.0:8080` |
| `preload_at_startup` | 启动时预加载模型，避免 Client 等待 |
| `inference_dtype` | 推理精度，推荐 `bfloat16` |
| `compile_model` | 是否 `torch.compile`，8GB 显存建议 `false` |
| `num_inference_steps` | diffusion 步数，推荐 `5` |
| `obs_queue_timeout` | 等待 observation 超时（秒） |

### `remote_gpu`（工控机 SSH 隧道）

| 字段 | 说明 |
|------|------|
| `ssh_host` | 远程 GPU 服务器 SSH 别名，如 `allinai2` |
| `use_ssh_tunnel` | 是否使用隧道，默认 `true` |
| `tunnel_local_port` | 工控机本地端口，默认 `8080` |
| `tunnel_remote_port` | 远程 GPU 服务器上 Server 端口 |

### `async_inference`（工控机 Client）

| 字段 | 说明 |
|------|------|
| `server_address` | Client 连接地址，隧道模式下为 `127.0.0.1:8080` |
| `policy_type` | 策略类型，固定 `pi05` |
| `policy_device` | 远程推理设备，固定 `cuda` |
| `actions_per_chunk` | 每次推理输出的动作步数，默认 `50` |
| `chunk_size_threshold` | queue 剩余比例低于此值时请求下一帧 obs，默认 `0.5` |
| `fps` | 控制频率，默认 `5`（每步 200ms） |
| `duration` | 运行时长（秒），默认 `40` |
| `execute` | 是否真发动作，`false` = dry-run |

### `policy_live`（本地推理 / Client 默认值）

提供 `policy_path`、`dataset_root`、相机控制参数等。Async Client 会读取其中与真机相关的字段；`async_inference` 中同名字段优先级更高。

## 异步推理工作原理（简述）

```
1. Client 发送 observation（含 4 路图像 + 关节状态）
2. Server 推理 → 返回 50 步 action chunk
3. Client 以 fps 逐步消费 action（如 5Hz）
4. 当 queue 消耗到 50%（25 步）时，发送下一帧 observation
5. Server 再推理 → 返回新 chunk
6. 循环直到 duration 结束或 Ctrl+C
```

因此看到 **25 步后 Server 才发起第二次推理** 是正常行为，不是卡住。

---

## 延迟构成（参考）

| 环节 | 典型耗时 |
|------|----------|
| 4 路相机采集 + obs 序列化/传输 | 数百 ms ~ 数秒 |
| Server 推理（bf16, 5 steps） | ~800ms |
| action 传回 + 入队 | 数十 ms |
| Client 控制周期（5 fps） | 200ms/步 |

## 常见问题排查

### 1. `connection attempt timed out` / `127.0.0.1:8080 UNAVAILABLE`

**原因：** gRPC 连不上 Server。

**检查：**

```bash
# 工控机：隧道是否在监听
ss -lntp | grep 8080

# 远程 GPU 服务器：Server 是否已启动并完成预加载
ssh allinai2 "ss -lntp | grep 8080"
```

**常见情况：**

- SSH 隧道终端未开或已断开 → 重新运行 `ssh_tunnel_policy_server.sh`
- Server 仍在预加载，尚未出现 `PolicyServer started` → 等待完成
- 启动顺序错误 → 严格按「Server → 隧道 → Client」

### 2. Client 启动后无 step 输出

- 确认 Server 端有 `Action chunk #N generated`
- 确认 Client 有 `Received action chunk steps [...]`
- 检查两端 `lerobot` 版本是否一致
- 确认 `async_robot_client.py` 为最新版（已修复 action queue 死锁）

### 3. 推理 25 步后 Server 不再输出

- 若为 dry-run 且 obs 被相似度过滤：确保使用最新 Client（threshold 发送时 `must_go=True`）
- 若为正常 chunk 切换：等待几秒，第二次推理约 800ms

### 4. Ctrl+C 退出慢

最新 Client 已在 Ctrl+C 时立即关闭 gRPC channel。若仍慢，检查是否有相机/机械臂 disconnect 阻塞。

### 5. `ModuleNotFoundError: grpc` / `lerobot.async_inference`

按前文安装对应 `requirements-async-pi05-*.txt`。
